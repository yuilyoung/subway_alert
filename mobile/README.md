# Android 앱 (데모)

Android 7.0 이상을 목표로 한 Expo/React Native 프로토타입입니다. Android 개발 도구가 설치된 환경에서 `npm ci` 후 `npx expo run:android`로 개발 빌드를 만듭니다. 위치 백그라운드 작업은 네이티브 권한·서비스 설정이 포함된 개발 빌드에서 확인해야 하며, Expo Go만으로 실기기 기능을 보장할 수 없습니다. 자바스크립트 단위 테스트는 `npm test`, Android JS 번들 검사는 `npx expo export --platform android`입니다.

앱에서 데모 역을 선택해 경로를 시작하거나 최대 5개 즐겨찾기를 저장합니다. 평일 시간대를 설정한 뒤 앱을 열어 출퇴근 감지 알림을 켜면 위치 포그라운드 서비스가 작동하며, 출발역 부근에 있을 때 확인 알림을 표시합니다. 실제 탑승 여부를 확정할 수 없으므로 경로 감시는 **사용자가 앱에서 직접 시작**해야 합니다. 수동 경로는 GPS가 신선하고 정확하며 이전 역 외부에서 근처로 들어온 경우에만 데모 하차 알림을 표시합니다. 한 정거장 경로는 즉시 데모 안내 후 종료합니다. 사용자가 알림·위치·백그라운드 위치 권한을 허용해야 합니다.

**실제 하차용이 아닙니다.** 포함된 2호선 5개 역 좌표는 검증되지 않은 대략값입니다. 지하 위치 손실, Android 절전·강제종료·재부팅 등으로 알림이 지연되거나 누락될 수 있습니다. 데모 하차 감시는 실제 열차나 역 방향을 확인하지 못하며 서버 열차 조회 또는 FCM과 연결되어 있지 않습니다. 역 시설도 실제 데이터가 없습니다. 새로운 역 직접 추가, 정확한 전국 역 검색, 환승 경로, 알림용 탑승 열차 확정·추적, 진짜 완전 자동 시작 및 실제 역 시설 정보는 미구현입니다.

백그라운드 작업은 사용자 설정을 직접 수정하지 않고 경로 ID별 별도 진행상태를 기록해 취소된 경로를 복원하지 않도록 합니다. 그러나 기기 환경에서 알림 발송과 취소/새 경로 시작이 동시에 발생할 때의 경쟁, OS에 의한 서비스 종료, 권한 회수, 알림 채널 및 위치 정확도는 실기기 테스트가 필요합니다. 화면에 표시되는 진행상태는 앱 복귀 시 새로고침됩니다.

## 열차 정보 조회 (시험 기능)

화면의 2호선 열차 조회에는 별도 Spring 서버가 필요합니다. 샘플 모드는 서울시 공개 `sample` 응답 최대 5건만 반환하며 탑승 열차 판별 및 하차 알림에 이용할 수 없습니다. 실시간 연동은 서버의 HTTPS 및 API 키 설정과 실제 환경 검증이 필요합니다. 열차 선택은 표시용이고 알림 감시와 연결되지 않습니다. 화면의 정보 시각은 서버가 서울시 시각을 서울 시간대로 해석한 값이며 실측이 필요합니다.

Metro 개발 모드(`__DEV__`가 true)에서는 에뮬레이터에서 PC 서버에 `http://10.0.2.2:8080`을, USB 연결 기기에서는 `adb reverse tcp:8080 tcp:8080` 이후 `http://127.0.0.1:8080`을 사용할 수 있습니다. Expo가 생성한 Android debug manifest는 디버깅을 위해 cleartext를 허용하지만 앱은 해당 두 주소와 localhost만 허용합니다. 독립 설치용 번들은 debug APK라도 `__DEV__`가 false일 수 있어 HTTP를 허용하지 않습니다. 일반 RN debug 빌드는 Metro 개발 서버 연결을 요구할 수 있습니다. 릴리스 및 독립 번들은 검증된 TLS와 유효한 인증서를 사용하는 HTTPS 서버가 필요합니다. 앱에 서울 API 키를 입력하거나 저장하지 않습니다. 이 구성은 Android 실기기에서 아직 검증되지 않았습니다.
