# 감시 등록 재시도와 응답 유실 복구

목표: POST 결과를 잃었을 때 새 감시를 중복 생성하지 않고, 앱 재시작 뒤에도 기존 요청을 조회·종료할 수 있게 한다. main의 TEST 앱·API 인증·Docker 구성을 보존한다. 외부 Firebase·실키·서버·DB는 생성하지 않는다.

## 방식

서버 응답을 평문 캐시하면 세션 비밀을 재보관해야 한다. 이번 구현은 앱이 미리 생성한 UUID와 256비트 세션 비밀을 안전하게 저장하고 서버가 그 UUID를 세션 ID로 사용하는 방식으로 정한다. 이는 구현 기본값이며 일반 사용자 계정 인증·분산 exactly-once를 뜻하지 않는다.

## 서버 계약

- POST `/api/monitor-sessions`: 기존 Bearer 외에 단일 `Idempotency-Key`(정규 UUID v4)와 `X-Session-Token`(소문자 16진수 64자)이 필수다. UUID가 생성 세션 ID가 되며 응답 sessionToken은 클라이언트 비밀과 동일하다. 서버는 비밀 해시만 보관한다. 기존 APK는 등록에 새 빌드가 필요하다.
- 같은 UUID·비밀·정규화한 요청 본문은 같은 세션의 현재 상태와 원래 만료시각을 반환한다. 재전송으로 생성·만료 연장·알림 재발송을 하지 않는다. 같은 UUID의 다른 비밀/본문은 정보 없는 409, 누락·형식 오류는 400이다. 원문 FCM/세션/API 토큰을 로그에 쓰지 않는다.
- 상태·취소는 기존 GET/DELETE `/{id}`와 X-Session-Token을 그대로 쓴다. 응답 유실이어도 앱이 ID와 비밀을 알고 있으므로 조회·종료할 수 있다.
- 취소가 먼저 도착한 경우 늦은 POST가 새 감시를 만들지 않도록, 알 수 없는 UUID라도 올바른 형식의 클라이언트 세션 비밀로 DELETE하면 CANCELLED 표식을 만든다. 같은 UUID/비밀의 늦은 POST는 CANCELLED를 반환하고 활성화하지 않는다. 다른 비밀은 404/409로 거부한다.
- 취소 표식도 기존 최대 500개 메모리 항목에 포함한다. 항목의 2시간 만료·추가 1시간 보관과 프로세스 재시작 시 손실은 유지한다. 한도 초과 취소/생성은 503, 기존 동일 요청 재생과 기존 세션 취소는 가능하다. 요청 제한은 재시도에도 적용한다.
- 동일·다른 요청 및 취소/생성 경쟁을 원자적으로 처리하고 네트워크 알림 작업은 기존처럼 잠금 밖에서 실행한다. 내부 도메인 테스트용 start(req)는 유지할 수 있지만 HTTP의 비멱등 등록 경로는 열지 않는다.

## 앱 계약

- Expo Crypto의 UUID v4와 32바이트 CSPRNG를 사용한다. 네이티브 FCM 토큰을 얻고 연결 일치를 재확인한 뒤, ID·세션 비밀·origin·API 키·원래 요청·관측시각을 PENDING 기록으로 SecureStore에 먼저 저장한다. 저장 실패 시 HTTP를 보내지 않는다.
- 성공 후 ACTIVE로 저장한다. 응답 유실·응답 형식 오류·최종 저장 실패 때 PENDING 정보를 보존하고 새 등록을 막는다. 한 SecureStore 항목과 UI의 동시 작업 잠금을 사용해 복구 정보가 빠지지 않게 한다. 기존 ACTIVE 기록도 읽을 수 있다.
- 등록 결과 조회는 기존 ID로 GET한다. 재시도는 같은 ID·비밀·본문을 사용하고 새 UUID/토큰을 만들지 않는다. 새 생성이 될 수 있는 POST 재시도는 원래 열차 관측이 60초 이내일 때만 허용한다. 그 이후에도 조회·취소는 가능하다. 자동 반복 전송은 하지 않는다.
- 앱 재시작 시 PENDING도 기존 감시처럼 조회·종료할 수 있고, 기기 토큰을 확인할 수 없는 복원 기록은 기존 정책대로 취소를 시도한다. 복원만으로 POST를 자동 전송하지 않는다. 취소 성공 전 기록을 지우지 않으며, 취소가 등록보다 앞서도 서버 표식이 늦은 생성을 막는다.
- 다른 origin으로 비밀을 보내지 않는다. 같은 origin의 새 API 키는 기존 세션 비밀과 함께 사용할 수 있다. 서버 메모리 재시작/보관 만료 이후의 중복 억제는 보장하지 않으며, 앱은 오래된 요청을 재생성하지 않는다.

실제 Android SecureStore·FCM·화면 꺼짐 시험은 아직 별도다. 이 작업의 기본 검증은 가짜 전송 경계로 응답 유실을 재현한 앱 도메인 테스트와 실제 서비스/HTTP 필터를 통과하는 서버 동시성·재생·취소 선행 테스트다.
