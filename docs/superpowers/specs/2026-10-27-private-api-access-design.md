# 개발 기기 API 접근과 호출 예산

사용자의 다음 작업 진행 지시에 따라, 기존 설계의 Tunnel 연결 전 API 보호 단계를 구현한다. 이 단계는 제한된 개발 기기용 사전 공유 키이며 일반 사용자 로그인이나 운영 배포 완료가 아니다. 기존 Expo/Java 17 구현과 TEST/LIVE 경계를 보존한다.

## 방식과 범위

Firebase/Supabase 사용자 로그인은 계정·프로젝트 설정이 미확정이다. 무인증 localhost 예외는 Tunnel이 로컬 프록시로 연결될 때 우회가 된다. 따라서 운영자가 생성한 기기별 무작위 Bearer 키를 서버 환경변수와 Android SecureStore에 등록하는 방식을 이번 구현의 기본값으로 선택한다. 앱에 공용 키를 내장하지 않는다. 키는 별도 경로로 전달하며 신뢰한 시험 참가자에게만 제공한다.

## 계약

- 서버 `SUBWAY_API_TOKENS`: 쉼표 구분 최대 20개, 각 32~128자의 base64url 문자. 비어 있으면 `GET /api/health` 외 모든 요청은 503, 잘못된 구성은 비밀값 없는 오류로 시작 실패. localhost/Forwarded 헤더 예외는 없다.
- 모든 보호 요청에 `Authorization: Bearer <key>` 필요. 중복/잘못된 헤더는 401. 세션 조회·종료에는 기존 `X-Session-Token`도 계속 필요하다. 원문 키를 로그·오류·URL에 넣지 않으며 상수 시간 해시 비교한다.
- 단일 프로세스 메모리 예산: 인증 전 전체 600회/분, 기기 키별 60회/분, 세션 생성 키별 3회/분. 분 예산은 token bucket으로 연속 보충한다. HTTP 429와 양의 정수 Retry-After를 반환한다. 동시 요청에도 한도를 넘겨 허용하지 않는다.
- 직접 열차 조회는 모든 키를 합쳐 6회/분 및 서울 날짜 하루 240회. 기존 시험 감시 폴링 600회/일과 별도이므로 sample 모드에서 합계 최대 840회/일/프로세스다. 재시작/복제 시 예산이 초기화/증가하므로 운영 과금 한도가 아니다.
- 앱: HTTPS origin과 키를 직접 입력·저장한다. origin 변경 시 키를 비우고 이전 응답을 무효화한다. 실제 전송은 `expo/fetch`, redirect:error, Authorization 헤더를 사용한다. 인증/429 거부는 알기 쉬운 오류로 표시한다. 키가 없거나 형식이 틀리면 전송하지 않는다.
- 등록한 감시의 origin·API 키·세션 토큰은 SecureStore에 함께 보존한다. 연결 주소를 바꿔도 기존 감시 비밀을 다른 origin으로 보내지 않는다. 취소 확인 전 정보를 삭제하지 않는다. 키 회수 시 취소 실패와 최대 2시간 만료를 안내한다.
- 로컬 Compose는 localhost/sample/FCM off를 유지하고 키 환경변수를 전달한다. 생성 도구는 파일을 독점 생성하고 권한 0600, 기존 파일은 덮어쓰지 않으며 키를 출력하지 않는다. 키 미설정 시 보호 API가 열리지 않는다.

직접 조회 240회는 클라이언트 요청의 허용 횟수입니다. 실키 LIVE 조회 한 번은 최대 5페이지의 서울 API 호출을 수행할 수 있어 외부 호출 840회 상한은 sample 모드에만 해당합니다. 실키의 통합 외부 호출 예산은 후속 구현이 필요합니다.

외부 Tunnel/VPS/DB/Play/Firebase 자원은 생성하지 않는다. 시험 참여자 키는 계정 소유권이나 FCM 기기 증명이 아니며 유출 시 재설정·서버 재시작이 필요하다. HTTP 개발 예외는 Metro의 루프백/에뮬레이터만 허용한다. 사용자 로그인, 영속/분산 쿼터, JSON 크기와 동시 작업 제한, 에지 DDoS 방어, 멱등 등록과 데이터 복구는 후속 운영 조건이다.
