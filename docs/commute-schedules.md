# 출퇴근 즐겨찾기 요일·시간 편집

외부 서버·API 키 없이 사용하는 로컬 데모 기능입니다. 최대 5개 즐겨찾기에 각기 다른 요일과 시간을 지정하고, 출발역 근처에서 탑승 확인 알림을 요청합니다. 실제 탑승·방향·하차를 자동 판정하는 기능은 아닙니다. 역은 기존 2호선 일부 5개이며 좌표도 대략값입니다.

## 사용 방법

1. 위쪽 검색에서 서로 다른 출발역·도착역을 선택합니다.
2. **새 즐겨찾기 조건**에서 월~일 중 하나 이상과 `HH:MM` 시각을 지정하고 추가합니다. 기본값은 월~금 07:00–09:00입니다.
3. 기존 항목의 **요일·시간 수정**을 누르면 그 항목의 조건을 편집합니다. 저장할 때까지 기존 감지 조건은 유지되고, 수정 취소는 저장하지 않습니다. 경로는 편집 중 표시된 기존 항목의 경로입니다.
4. **조건 수정 저장**은 ID와 자동 감지 사용 여부를 보존합니다. 5개가 차도 수정할 수 있으며, 저장 중 삭제된 항목을 새 즐겨찾기로 복원하지 않습니다. 저장 실패 시 입력을 유지합니다.
5. 앱에서 **출퇴근 감지 알림 켜기**를 선택하고 알림·위치·백그라운드 위치 권한을 허용합니다. 확인 알림 후 경로 감시는 앱에서 직접 시작합니다.

기존 저장 키와 역·즐겨찾기 ID는 바뀌지 않습니다. 기존 평일 조건도 그대로 읽습니다. 빈 요일, 범위 밖 요일, 24:00 같은 잘못된 시각, 시작과 종료가 같은 조건은 저장하지 않습니다. 손상된 조건은 자동 감지에서 제외하고 화면에 확인이 필요하다고 표시합니다.

## 야간 조건과 날짜

기기 현지 시간을 사용하며 시작은 포함하고 종료는 제외합니다. 종료 시각이 시작보다 빠르면 다음 날까지입니다. 요일은 시간대가 **시작한 날**을 뜻합니다.

| 설정 | 현재 시각 | 조건 일치 |
| --- | --- | --- |
| 월 07:00–09:00 | 월 07:00 | 예 |
| 월 07:00–09:00 | 월 09:00 | 아니요 |
| 일 23:00–01:00 | 일 23:30 | 예 |
| 일 23:00–01:00 | 월 00:30 | 예, 일요일에 시작한 같은 시간대 |
| 일 23:00–01:00 | 월 01:00 | 아니요 |

같은 즐겨찾기의 같은 시간대에는 자정 전후로 제안을 중복 요청하지 않습니다. 다음 적격 시작 날짜에는 다시 제안할 수 있습니다. 요일·시간을 바꾸면 새 조건의 시간대가 적용되며, A→B→A로 되돌려도 보관 중인 A의 소비 기록을 유지합니다. 이력은 현재·전일 시작 날짜와 미래 기록을 보수적으로 보관하고 그보다 오래된 과거 기록을 정리합니다. 즐겨찾기 하나에 최대128개이며 한도가 찼거나 이력이 손상되면 기존 기록을 덮어쓰지 않고 해당 항목의 새 제안을 보류합니다. 다른 적격 항목은 계속 확인합니다. 기존 날짜만 저장한 일별 마커도 해당 날짜 또는 야간 시작 날짜에 억제 기록으로 인정합니다.

## 비동기 처리와 알림 경계

한 위치 이벤트에서는 적격 즐겨찾기에 최대 한 번 제안합니다. 이미 제안한 첫 항목은 건너뛰고 다음 적격 항목을 찾습니다. 최신 위치가 부정확하거나 오래됐으면 제안하지 않습니다. 제안 전과 마커 저장 후에 자동 감지·진행 경로·즐겨찾기 존재/사용 여부·경로·요일/시간을 다시 확인하므로 처리 중 수정·삭제·중지·새 경로 시작이 확인되면 이전 조건의 알림을 억제합니다. 완료된 경로는 별도 진행 기록을 읽어 종료 상태로 해석하며 이후 출퇴근 제안을 막지 않습니다. 진행 기록 I/O가 끝난 뒤 설정을 다시 읽어 그 사이의 중지·새 경로·조건 수정도 반영하고, 완료한 같은 경로 ID만 종료 상태로 해석합니다.

같은 JS 실행 환경의 겹친 이벤트를 직렬화합니다. 알림 요청 전에 마커를 저장하므로 저장 실패에는 알리지 않습니다. 알림 요청이 실패해도 마커를 유지하고 그 시간대에 자동 재시도하지 않습니다. 따라서 중복 요청 억제와 실제 알림 수신 보장은 다릅니다. OS의 서로 다른 실행 환경에 걸친 원자적 중복 억제, 이미 시작된 알림의 회수, 권한 거부·절전·강제 종료·재부팅에서의 수신 보장은 제공하지 않습니다.

## 실제 검증과 남은 일

Node 테스트는 실제 일정 계산·즐겨찾기 저장 적용·제안 처리 함수와 실제 저장 모듈을 사용합니다. 저장 장치·시계·알림 호출 경계만 시험 대역으로 대체해 일→월 야간·A→B→A 편집과 이력 한도/구형 기록, 시작/종료 경계, 5개에서 수정, ID/사용 여부 보존, 오래된 초안·삭제·중지·시간 경과, 겹친 콜백, 마커/알림 실패와 완료된 경로 뒤 재제안을 검증합니다. 테스트 수와 Android 빌드 결과는 해당 PR에 기록합니다.

`npm test`와 `npx expo export --platform android`는 Android 화면 터치·권한·백그라운드 서비스·실제 알림 표시를 검증하지 않습니다. 시험 APK를 실제 기기에 설치해 요일 선택/편집/취소, 야간 날짜 경계, 알림/위치 권한 거부, 화면 꺼짐·Doze·강제 종료·재부팅을 별도로 시험해야 합니다.

이 기능은 Firebase·서울 실시간 키가 필요하지 않습니다. 별도 서버 TEST/FCM 기능은 기존 설정이 필요하고 실제 자격 증명·기기 수신은 여전히 미검증입니다. 전체 역/시설·검증된 경로/좌표·LIVE 하차 판단·Supabase 운영 연결·Tunnel·VPS·Google Play 배포도 미완료입니다.
